# 实拍数据集

用来核对拍照识别准确率，以及给「自动框选」当 ground truth。

> **照片本身不在版本控制里**（见根目录 `.gitignore`）：背景拍到了住处，
> 而且 26MB 进 git 历史就删不掉了。标注、框、编辑器、评测脚本都在仓库里。
> 换台机器要跑评测的话，把 `01.HEIC … 12.HEIC` 放回 `data/`，再按下面的步骤
> 重新生成 `preview/` 即可。

```
data/
  01.HEIC … 12.HEIC     原始照片（不入库，重命名自 IMG_98xx，对照表见 labels.md）
  labels.md             每张的手牌 / 碰杠标注（已经你复核，v2）
  boxes.json            每张「手牌 + 碰杠」的框（本文件说明如何编辑）
  preview/              编辑器用的 JPEG（方向已烘进像素，长边 1400）
  editor/               框选编辑器
```

## 打开编辑器

```bash
python3 data/editor/serve.py
```

浏览器会自动打开 `http://localhost:8777`。改动**即时写回** `data/boxes.json`，不用手动导出。

或者在 Claude Code 里用 `.claude/launch.json` 里的 `box-editor` 配置启动。

## 怎么框

**只框住「自己的手牌 + 自己碰/杠出来的牌」，尽量贴边。**
桌上其他人的牌、中间的弃牌堆、牌墙都不要框进去。

右侧面板会显示这张照片里应该被框住的牌（取自 `labels.md`），可以对照着数。

| 操作 | 方式 |
|---|---|
| 移动 | 拖框内部，或方向键（`⌥`+方向 = 大步） |
| 缩放 | 拖八个把手，或 `⇧`+方向键（调右/下边） |
| 重画 | 在框外按住拖出一个新框 |
| 切换照片 | 点左侧缩略图，或 `J` / `K` |
| 精调 | 拖动时右上角有放大镜（3.5×），用它对齐牌的边缘 |

左侧缩略图右上角有 `●` 表示这张相对初始值改过。

## boxes.json 的格式

相对坐标，`0–1`，**左上角为原点**，坐标系是「照片摆正之后」的（也就是
App 里 `normalizedUp()` 之后、`preview/` 里那个方向）：

```json
"05": {"x": 0.0400, "y": 0.5150, "w": 0.9300, "h": 0.2580}
```

## 打底框是怎么来的

我先逐张放大照片，量出手牌行与副露的实际边界，人工填了一版初始值，
然后渲染出来目测校正了两轮。**这只是打底，精度不够的地方请直接在编辑器里改。**

已知偏松的地方：

- **05**：手牌行和 `2p 4p 5p 6p` 之间隔着一片空毡面，框必须跨过去，
  左上角会带进两张弃牌，几何上避不开。
- **10**：`碰1p` 那三张在正中间，框的左右两侧因此比牌宽出不少。
- **01 / 04**：旁边有单独立着的散牌紧挨着自己的牌，边界不好完全切干净。

## 评测：自动框 vs ground truth

`boxes.json` 是自动框选的 ground truth。评测走 App 里**真正的代码路径**
（`LocalTileRecognizer.suggestHandRegion()`），不是另写一份推理——
免得「照着重写的版本调出来的参数，装回 App 里不灵」。

```bash
# 1. 装 Debug 版到模拟器
xcodebuild -project "majiang calculator.xcodeproj" -scheme "majiang calculator" \
  -destination 'id=<SIM_UDID>' -derivedDataPath /tmp/dd build
xcrun simctl install <SIM_UDID> "/tmp/dd/Build/Products/Debug-iphonesimulator/majiang calculator.app"

# 2. 把 preview 图拷进 App 容器
C=$(xcrun simctl get_app_container <SIM_UDID> ACM.majiang-calculator data)
mkdir -p "$C/Documents/eval" && cp data/preview/*.jpg "$C/Documents/eval/"

# 3. 用 MJ_EVAL=1 启动，控制台会打出每张的框
SIMCTL_CHILD_MJ_EVAL=1 xcrun simctl launch --console-pty \
  --terminate-running-process <SIM_UDID> ACM.majiang-calculator > eval.log
```

`eval.log` 里每张一行 `EVAL <编号> x y w h`，另有 `DET <编号> [...]` 是原始检测框
（供离线调算法用，不必每次改参数都重编 App）。评测代码在
`majiang calculator/BoxEval.swift`，`#if DEBUG` 包着，不进 Release 包。

### 当前结果

| | 平均 IoU | IoU≥0.7 | 裁到自己的牌 |
|---|---|---|---|
| 改之前（空间连通扩张） | 0.332 | 0/12 | 0 |
| **现在（框高 + 闭包）** | **0.811** | **10/12** | **0** |

改之前每张框都是 `x=0, w=1.0` 撑满全宽、面积超出 1.1–4.2 倍，等于没有排除作用。

现在的判据是**框高**：实拍里自己的牌框高 0.049–0.110，桌上弃牌 0.019–0.054，
12 张里 11 张能干净分开（弃牌又远又平摊，被透视双重压缩）。参数
`nearFieldRatio = 0.70` / 外扩 `0.20` 张牌高 / 闭包吸收 `0.5` 都在这 12 张上扫过，
0.70 是明确的甜点：再往上抬会开始裁掉自己的牌且 IoU 反降。

**还差的两张**：03（IoU 0.44）和 06（0.48）都是薄薄的单排手牌，
各有一个弃牌框被多包进来，把框的高度撑了一倍。03 尤其是硬骨头——
它那个弃牌框比手牌里最矮的还高（0.0535 vs 0.0510），**纯高度判据在这张上物理不可分**，
要再进一步得引入别的信号（成排结构、密度）。

加照片后重跑评测即可看到新的数字；`boxes.json` 里补上对应编号的框就行。

## 评测：识别准确率

同一次运行还会打出 `REC <编号> hand=[…] melds=[…]`，走的是用户的实际路径
（自动框 → 裁剪 → `recognize()`）。用 `labels.json`（`labels.md` 的机读版）判分：

```bash
python3 <脚本> eval.log      # 见 git 历史里的 recacc.py
```

### 当前结果

| | 牌面全对 | 牌面+分组全对 |
|---|---|---|
| 分组改之前 | 7/12 | 3/12 |
| **现在** | **8/12** | **7/12** |

**关键修复**：`parseMeldRuns` 原本把「孤立单张」当暗杠，导致几乎任何一簇牌都能
「解析成副露」，于是手牌簇选错、还凭空造出好几组暗杠（照片 11 一张就造了 4 组，
张数从 13 涨到 21）。现在改成**严格解析优先**，只有当「猜暗杠」能让张数
凑成 13/14 时才采纳——真的暗杠会让张数成立，被切开的手牌不会。
另外把切簇阈值从 0.55 放宽到 0.9 张牌宽，立着摆的手牌不会再被切碎。

### 剩下 5 张的性质（不是同一类问题）

- **模型认错（01、04）**：`4s` 读成 `6s`、`2m` 读成 `3m`。两张的牌都是**平摊**的，
  模型多半是拿立着的牌训练的。要改得换模型或补数据，算法层面无解。
- **框太松放进弃牌（03、06）**：正是 IoU 最低的两张（0.44 / 0.48），
  多出来的弃牌让张数对不上，被 `hasValidTileCount` 拦下并提示核对。
- **物理上不可分的歧义（03、05）**：05 把手里的 `4s×3` 判成碰——照片上三张同牌摆一排，
  谁也分不出是手握还是碰的。03 输出的分组和 04 的 ground truth 完全一致，
  因为这两张照片的牌本来就一样，只是立排 vs 平摊方阵。

也就是说 12 张里真正「算错」的只有 01 和 04 两张，且都是模型分类问题；
其余要么正确，要么被张数校验挡下来让用户核对，没有静默出错的情况。
