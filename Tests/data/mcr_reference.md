## 任务 2：不重复原则（最容易实现错的部分）

### 2.1 五大计分原则（原文）

规则第 3.9.1.5 条「计算基本分的原则」。**先确定分值最高的主番，再按以下原则累加其余番种**。

【B】中文原文（维基百科·国标麻将，转录自 98 规则）：

1. **不重复原则**：「当某个番种，由于组牌条件所决定，在其成立的同时，必然并存着其它番种，则其它番种不重复计分。」
2. **不拆移原则**：「确定一个番种后，不能将其自身再拆开互相组成其它番种计分。」
3. **不得相同原则**（又称不选加原则）：「凡已组合过某一番种的牌，不能再同其它一副牌组成相同的番种计分。」
4. **就高不就低原则**：「有两副以上的牌，有可能组成两个以上的番种，而只能选其中一种计分时，可选择分值较高的番种计分。」
5. **套算一次原则**：「如有尚未组合过的一副牌，只可同已组合过的相应的一副牌套算一次。」

【A】官方英译（mcr_EN.pdf §3.9.1.5，逐字）：

> (1) The Non-Repeat Principle: When a fan is inevitably implied or included by another fan, both fan may not be scored.
> (2) The Non-Separation Principle ("Unbreakable"): After combining sets to create a fan, it is forbidden to rearrange those same sets to create a different fan.
> (3) The Non-Identical Principle: Once a set has been used to create a fan, it is not allowed to use the same set together with other sets to create the same fan.
> (4) Freedom to Choose the Highest Points ("the High-versus-Low Principle"): If you can use a set to form both a high-score fan and a low-score fan, it is your right to choose the high-score fan.
> (5) The Account-Once Principle ("Exclusionary rule"): When you have combined some sets to create a fan, you can only combine any remaining sets once with a set that has already been used.

**工程含义（这是实现的核心）：**

- 原则 2（不拆移）⇒ **必须先把 14 张牌固定拆成一个划分（33332 / 七对 / 特殊型），再对这个划分算番**；不允许同一手牌里用 A 划分算一个番、用 B 划分算另一个番。
- 原则 4（就高不就低）⇒ 枚举所有合法划分，**取总分最高的那个划分**作为结果。参考实现 A 正是这么做的（`MAX_DIVISION_CNT 20`，逐划分算番取 max）。
- 原则 3 + 5 ⇒ 一般高 / 喜相逢 / 连六 / 老少副 这四个 1 分「两副顺子」番种的**计数上限**问题，见下 2.4。这是全规则最难写对的一处。

【B】教学书给的两个关键例子（mahjongsoft Book Ch.2）：

- 原则 5 例：`234567p 234567s`（两色各两副顺子）**只能算「喜相逢×2 + 连六×1」或「喜相逢×1 + 连六×2」，不能算「喜相逢×2 + 连六×2」**。
- 原则 3+5 例：`234s 223344567p` 只能算「一般高、喜相逢、连六」，不能算「喜相逢×2、连六」。

### 2.3 你问到的具体问题（逐条回答，含引擎实测）

以下每条都用 `PyMahjongGB` 实跑验证过。

**Q：大四喜是否还计 圈风刻/门风刻/三风刻/碰碰和？**
**A：全部不计。**
【已用引擎实测】东东东 南南南 西西西 北北北 中中（圈风东、门风东，自摸）
→ `大四喜88 + 字一色64 + 四暗刻64 + 自摸1 = 217 番`
注意：**即使有东风刻且圈风门风都是东，也不出圈风刻/门风刻**。这是最常见的实现 bug 之一。

**Q：清幺九是否还计 碰碰和/双同刻/幺九刻？**
**A：碰碰和、幺九刻、全带幺、无字一律不计；双同刻也不计（现行通行计法）。**
【已用引擎实测】111万 999万 111饼 999饼 11条（全暗，自摸）
→ `清幺九64 + 四暗刻64 + 单钓1 + 自摸1 = 130 番`（无碰碰和、无双同刻、无幺九刻）
⚠️ **存疑点**：严格 98 规则连**三同刻**也不计，现行通行计法则允许三同刻。参考实现 A 用 `#ifdef STRICT_98_RULE` 把这一条做成了编译开关。你需要选定一档。

**Q：绿一色是否还计 清一色/混一色？**
**A：有「发」→ 计混一色不成立（不计）；**无「发」→ 可以计清一色。**
【已用引擎实测】222条 333条 444条 666条 88条（全暗自摸，无发）
→ `绿一色88 + 四暗刻64 + 清一色24 + 一色三节高24 + 断幺2 + 自摸1 = 203 番`
另一例（有发）：`[234条,吃][666条,碰] 33条 888条 发发发 自摸` → `绿一色88 + 双暗刻2 + 箭刻2 + 自摸1 = 93 番`（无混一色）

**Q：九莲宝灯是否还计 清一色/不求人？**
**A：都不计。自摸时只计「自摸」1 分，不计「不求人」4 分。**
【已用引擎实测】1112345678999万 自摸 1万
→ `九莲宝灯88 + 清龙16 + 四归一2 + 自摸1 = 107 番`
点和 2 饼那例：`1112345678999饼 + 2饼` → `九莲宝灯88 + 双暗刻2 + 幺九刻1 + 连六1 = 92 番`
⚠️ **存疑点**：英译本写 "Does not combine with Full Flush, Concealed hand, and **Pung of Terminals or Honors**"，即不计幺九刻；但两套中文引擎在上面这例里都算了 1 个幺九刻。差 1 分。

**Q：十三幺是否还计 混幺九/单钓将？**
**A：不计五门齐、门前清、不求人、单钓将；混幺九本身牌型不成立（十三幺不是刻子型）。**
【已用引擎实测】十三幺自摸 → `十三幺88 + 自摸1 = 89 番`

**Q：七星不靠 / 全不靠 / 组合龙 之间的关系？**
- **七星不靠（24）**：7 种字牌全齐 + 3 花色各取一条 147/258/369 的 7 张序数牌。**不计五门齐、不求人、单钓将、门前清**，也**不计组合龙**（序数牌只有 7 张，凑不满 9 张龙）。
  【已用引擎实测】→ `七星不靠24 + 自摸1 = 25 番`
- **全不靠（12）**：字牌可以少于 7 种，序数牌 7–9 张。**不计五门齐、不求人、单钓将、门前清**。
- **全不靠 + 组合龙**：当全不靠的序数牌恰好是完整 9 张（147/258/369 三色齐）时，**两者复合 = 12+12 = 24 分**。
  【已用引擎实测】369万 147饼 25条 南西北中发 + 8条 → `全不靠12 + 组合龙12 + 自摸1 = 25 番`
- **组合龙（12）单独出现**：组合龙 9 张 + 一副面子 + 将（普通和型）。此时可另计平和、五门齐、箭刻。
  例：`[FFF,碰] 147万 258饼 39条 西西 + 6条` → `组合龙12 + 五门齐6 + 箭刻2 = 20 番`

**Q：一色四同顺 / 一色四节高 / 一色四步高 各自还能计什么？**
- **一色四同顺（48）**：不计一色三同顺、一般高、**四归一**（这是最常见的错算点——4 副相同顺子必然有 4 张相同牌，但不给四归一）。可另计清一色/绿一色/断幺/平和/全中/全带五/缺一门。
  【已用引擎实测】456条×4 + 55万（自摸）→ `一色四同顺48 + 全中24 + 全带五16 + 不求人4 + 平和2 + 缺一门1 = 95 番`
- **一色四节高（48）**：不计一色三节高、碰碰和。可另计四暗刻、小于五、推不倒、幺九刻、缺一门。
  【已用引擎实测】111条 222条 333条 444条 22饼（全暗自摸）→ `四暗刻64 + 一色四节高48 + 小于五12 + 幺九刻1 + 缺一门1 + 单钓1 + 自摸1 = 128 番`
- **一色四步高（32）**：不计一色三步高、连六、老少副。可另计清一色/混一色、平和。
  【已用引擎实测】123万 234万 345万 456万 99饼（门清）→ `一色四步高32 + 不求人4 + 平和2 + 缺一门1 + 单钓1 = 40 番`

### 2.4 小番在大番存在时的计法

| 小番 | 规则 |
|---|---|
| **四归一（2）** | 只在**顺子/刻子/将**中出现 4 张相同牌时计；**杠不算四归一**。可以计多次（一手最多 3 次，实测有 `四归一×3` 的案例）。**一色四同顺不计四归一**；九莲宝灯**可以**计四归一。 |
| **箭刻（2）** | 大三元、小三元、双箭刻存在时**一律不计**；字一色、混幺九、五门齐、三风刻、四杠等**可以**另计。 |
| **圈风刻（2）/ 门风刻（2）** | **大四喜不计**。小四喜、字一色、混幺九、三风刻、四杠**都可以计**。<br>【已用引擎实测】字一色例（东东东 南南南 中中中 发发发 白白，圈风东门风东）→ `小三元64 + 字一色64 + 四暗刻64 + 圈风刻2 + 门风刻2 + 单钓1 + 自摸1 = 198 番` |
| **幺九刻（1）** | 被以下番种吸收（不计）：大四喜、小四喜、清幺九、字一色、混幺九、大三元/小三元中的箭刻部分。<br>**三风刻**特殊：三风刻成立时，那 3 副风刻的幺九刻要**减掉 3 个**，但手里其它的幺九刻照常计。<br>可以计多次（实测有 `幺九刻×4`）。 |
| **无字（1）** | 被平和、断幺、清一色、全大、全中、全小、大于五、小于五、全双刻、全带五、三色双龙会、一色双龙会全部吸收。 |
| **缺一门（1）** | 被绿一色、字一色、推不倒、一色双龙会吸收。<br>⚠️ 严格 98 规则下还被大三元、小三元、一色四同顺、一色四节高、一色四步高、三风刻吸收；现行通行计法**保留**。参考实现 A 的 `STRICT_98_RULE` 开关正是这一组。 |
| **自摸（1）** | 被不求人、妙手回春、杠上开花吸收（这三个成立时不再计自摸）。 |
| **单钓将（1）** | 被四杠、全求人、七对、十三幺、七星不靠、全不靠、连七对吸收。 |
| **门前清（2）/ 不求人（4）** | 互斥（点和 vs 自摸）。**必然门清的番种**（七对、十三幺、七星不靠、全不靠、连七对、九莲宝灯、四暗刻）自摸时**只计自摸 1 分，不计不求人 4 分**。 |

## 任务 4：最容易算错的边界情况

> 牌型记法：`123m` = 一二三万，`456p` = 四五六饼，`789s` = 七八九条，`东东东` 等直接写；`[碰]`/`[吃]`/`[明杠]`/`[暗杠]` 标注副露。

### 1. 大四喜 + 圈风/门风 —— **不给圈风刻门风刻**
- 牌例：东东东 南南南 西西西 北北北 中中，圈风东、门风东，自摸
- **正确**：大四喜 88 + 字一色 64 + 四暗刻 64 + 自摸 1 = **217 番**【已用引擎实测】
- **常见错算**：加上 圈风刻 2 + 门风刻 2 = 221；或再加碰碰和 6 / 幺九刻。
- 对照：**小四喜、字一色、混幺九、三风刻 都可以计圈风刻/门风刻**——只有大四喜不行。

### 2. 三风刻 —— **减 3 个幺九刻，但保留圈风刻门风刻**
- 牌例：东东东 南南南 西西西 123p 9p，门清**自摸** 9p（99p 作将）
- **正确**：三暗刻 16 + 三风刻 12 + 混一色 6 + 全带幺 4 + 不求人 4 + 圈风刻 2 + 门风刻 2 + 单钓将 1 = **47 番**【已用引擎实测】
- **常见错算**：给 3 个风刻各计 1 分幺九刻（+3）；或者反过来把圈风刻/门风刻也一并吞掉（-4）。
- 源码依据：`fan_table[PUNG_OF_TERMINALS_OR_HONORS] -= 3`（是**减 3**，不是清零——手里别的幺九刻仍要计）。

### 3. 一色四同顺 —— **不给四归一**
- 牌例：456s 456s 456s 456s + 55m（门清自摸 6s）
- **正确**：一色四同顺 48 + 全中 24 + 全带五 16 + 不求人 4 + 平和 2 + 缺一门 1 = **95 番**【已用引擎实测】
- **常见错算**：加 四归一×3（4s/5s/6s 各 4 张）= +6 分。规则明写"一色四同顺不计四归一"。
- 对比：**九莲宝灯可以计四归一**（1112345678999 + 1 → 四归一 2 分）。

### 4. 九莲宝灯自摸 —— **只计自摸 1 分，不计不求人 4 分**
- 牌例：1112345678999m，自摸 1m
- **正确**：九莲宝灯 88 + 清龙 16 + 四归一 2 + 自摸 1 = **107 番**【已用引擎实测】
- **常见错算**：算成 不求人 4 分 → 110；或者再加清一色 24 → 134。
- 同类："必然门清"的番种（七对、十三幺、七星不靠、全不靠、连七对、四暗刻、九莲宝灯）自摸时都只计自摸。
- ⚠️ 存疑：98 规则原文只对七对/七星不靠等**明写**了"不计不求人"，对九莲宝灯/四暗刻**没写**；现行通行规则统一按只计自摸处理。也有部分规则一律计不求人。**建议做成配置项。**

### 5. 四暗刻 —— **不求人降级为自摸**（不是简单删除）
- 源码：
  ```cpp
  if (fan_table[FOUR_CONCEALED_PUNGS]) {
      fan_table[ALL_PUNGS] = 0;  fan_table[CONCEALED_HAND] = 0;
      if (fan_table[FULLY_CONCEALED_HAND]) {
          fan_table[FULLY_CONCEALED_HAND] = 0;
          fan_table[SELF_DRAWN] = 1;          // ← 降级，不是清零
      }
  }
  ```
- **常见错算**：直接把不求人清零，结果连自摸的 1 分也丢了。

### 6. 清幺九 —— 不计双同刻，但 **可以** 计三同刻（现行）
- 牌例：111m 999m 111p 999p 11s（全暗，自摸 1s）
- **正确（现行）**：清幺九 64 + 四暗刻 64 + 单钓将 1 + 自摸 1 = **130 番**【已用引擎实测】
- 牌例：`[碰111m] 111p 999p 11s 99s`，自摸 1s（成 111s，99s 作将）→ 清幺九 64 + 三暗刻 16 + 三同刻 16 + 自摸 1 = **97 番**
- **常见错算**：给双同刻（111m+111p，999m+999p）各 2 分；或加碰碰和 6、幺九刻 4、全带幺 4、无字 1。
- ⚠️ **存疑**：严格 98 规则连三同刻也不计。

### 7. 绿一色 —— 有没有「发」，结果差 24 分
- 无发：222s 333s 444s 666s 88s（全暗自摸）→ 绿一色 88 + 四暗刻 64 + **清一色 24** + 一色三节高 24 + 断幺 2 + 自摸 1 = **203 番**【已用引擎实测】
- 有发：`[吃234s][碰666s] 33s 888s 发发`，自摸发 → 绿一色 88 + 双暗刻 2 + 箭刻 2 + 自摸 1 = **93 番**（**无混一色**）
- **常见错算**：无发时漏掉清一色（-24）；有发时误加混一色（+6）。

### 8. 七对 与 大牌型的复合 —— 98 规则 vs 现行规则冲突
- 牌例：1199m 1199p 1199s + 11m（七对型的清幺九）
- **现行通行**：清幺九 64 + 七对 24 + 四归一 2 + 自摸 1 = **91 番**【已用引擎实测】
- **严格 98 规则**：字一色/清幺九/混幺九定义要求"由刻子、将组成"，七对型不满足，**只能计七对 + 缺一门**。
- 【B】维基百科明确把这条列为"七对与其他番种的复合争议"。**现行规则允许绿一色、字一色、清幺九、混幺九、全大、全中、全小、大于五、小于五复合七对，但字一色/清幺九/混幺九仍不计碰碰和。**
- **建议：做成配置项，默认现行。**

### 9. 一明杠 + 一暗杠 —— 3 分还是 5 分？
- 牌例：`[暗杠 1111m][明杠 9999p] 234s 234p 77s`（和 7s）
- **现行通行**：明暗杠 **5 分**（一个独立的非官方番种）→ 实测 `喜相逢1 + 幺九刻2 + 无字1 + 单钓将1 + 明暗杠5 = 10 番`【已用引擎实测】
- **严格 98 规则**：规则只写了双明杠(4)、双暗杠(6)，一明一暗只能拆开算 明杠 1 + 暗杠 2 = **3 分**。
- 两套引擎都把它做成可选项（`SUPPORT_CONCEALED_KONG_AND_MELDED_KONG`）。**必须做成配置项。**

### 10. 杠系列 与 暗刻系列 的复合上限
- 牌例：`[暗杠1111s][暗杠2222m] 333p 444p 88s` → 四暗刻 64 + 三色三节高 8 + **双暗杠 6** + 幺九刻 1 + 无字 1 + 单钓将 1 = **81 番**
- 牌例：`[暗杠1111s][暗杠2222m][暗杠3333p][暗杠4444p] 88s` → 四杠 88 + 四暗刻 64 + 三色三节高 8 + 幺九刻 1 + 无字 1 = **162 番**
- **规则**：现行通行——杠系列（四杠/三杠/双暗杠/双明杠/明暗杠）与暗刻系列（四暗刻/三暗刻/双暗刻）复合时，**最多各取一个**；且**双暗杠不再计双暗刻**。
- 【B】98 规则原文没写杠刻如何复合，维基把它列为"杠刻复合计分争议"。
- **常见错算**：把 4 个暗杠既算四杠又算四暗刻**又**算双暗杠/暗杠×4。

### 11. 和绝张 / 抢杠和 —— **不能只看外部 flag，要用牌数校验**
参考实现在算番前有一段"校正和牌标记"，这是实现者几乎必错的地方：
```cpp
// 如果立牌包含和牌，则必然不是和绝张
if (standing_table[win_tile] != 1) win_flag &= ~WIN_FLAG_LAST_TILE;
// 如果和牌在副露中出现3张，则必然为和绝张
if (3 == fixed_table[win_tile])   win_flag |=  WIN_FLAG_LAST_TILE;
// 自摸+杠标记：手牌没有杠 → 不是杠上开花
// 点和+杠标记：和牌张在自己手牌/副露中出现过 → 不是抢杠和
if (fixed_table[win_tile] != 0 || standing_table[win_tile] != 1)
    win_flag &= ~WIN_FLAG_KONG_INVOLVED;
```
- 例：手里有 `99p` 作将、和 `9p`，即使 UI 勾了"绝张"，**也不能算和绝张**（自己就拿着 3 张）。
- 例：`[碰666m][碰777m][碰999m] 7888m` 和 6m → **自动就是和绝张**（副露里已有 3 张 6m），不需要外部 flag：实测 `清一色24 + 大于五12 + 和绝张4 + 四归一4 + 幺九刻1 = 45 番`。
- **抢杠和不计和绝张**（规则明写）。

### 12. 边张 / 坎张 / 单钓将 —— **必须是"独听"，且牌位置不能有歧义**
- `12345m` 和 `3m`：**不算边张**（3m 既可补 123 也可补 345）。实测：`花龙8 + 门前清2 = 10 番`（无边张）
- `12m` + 其它已成型，和 `3m`：**算边张**。实测：`花龙8 + 门前清2 + 喜相逢1 + 独听・边张1 = 12 番`
- `4556m` 和 `5m`：**算坎张**（官方原文明确"4556和5也为坎张"）。实测：`花龙8 + 门前清2 + 平和2 + 喜相逢1 + 独听・嵌张1 = 14 番`
- `45567m` 和 `6m`：**不算坎张**（多面听）。
- **常见错算**：只判"和牌张在两张之间"就给坎张，不判是否唯一听、不判是否唯一放置位置。

### 13. 平和 —— 将必须是序数牌，且不计无字
- 牌例：`234m 567m 234p 567s 白白` 和牌 → **无平和**（白板作将）。实测：`花龙8 + 门前清2 = 10 番`
- 牌例：`234m 567m 234p 567s 88p` → 平和 2 分，但**不再计无字 1 分**。
- **常见错算**：字牌作将也给平和；或平和 + 无字 一起算。同理**断幺也不计无字**。

### 14. 四归一 —— 杠不算，但可以算多次
- 牌例：`[碰666m][碰777m][碰999m] 7888m` 和 6m → **四归一 ×2**（6m 四张、8m 四张）= 4 分
- 牌例：`[碰111m][吃123m] 3345555m` 自摸 3m → 清一色 24 + **四归一×3**（1m/3m/5m）+ 幺九刻 1 + 自摸 1 = **32 番**
- **常见错算**：杠出来的 4 张也给四归一；或者只算一次。

### 15. 无番和 —— 定义是"0 番"，不是"低番"
- 牌例：`[吃123m][吃345m] 678p 56s 东东` 和 7s
- **正确**：无番和 8 分（+ 花牌另算）。实测：`无番和8 = 8 番`；带 2 花 → `无番和8 + 花牌1 + 花牌1 = 10 番`
- **常见错算**：算出 1–7 番就当无番和；或算出 0 番后没有替换成无番和。正确逻辑是：**跑完全部流程，若总分为 0，才置为无番和 8 分**（源码流程第 13 步）。
- 注意：花牌**不计入起和的 8 分门槛**，也不阻止无番和成立。

### 16. 全求人 —— 不计单钓将；和的必须是别人打的
- 牌例：`[吃234m][吃345p][吃234s][明杠中] 11m` 和 1m
- **正确**：全求人 6 + 箭刻 2 + 明杠 1 + 喜相逢 1 = **10 番**【已用引擎实测】
- **常见错算**：加单钓将 1 分。

### 17. 妙手回春 / 杠上开花 —— **不计自摸**；海底捞月照常
- `妙手回春`：三色三同顺 8 + **妙手回春 8** + 不求人 4 + 平和 2 + 单钓将 1 = **23 番**（不再有自摸 1）
- `杠上开花`：`[暗杠1111m] 234p 567s 678p 白`，杠后自摸白（白白作将）→ 杠上开花 8 + 不求人 4 + 暗杠 2 + 幺九刻 1 + 单钓将 1 = **16 番**
- `海底捞月`（点和最后一张）：三色三同顺 8 + 海底捞月 8 + 门前清 2 + 平和 2 + 单钓将 1 = **21 番**
- **常见错算**：妙手回春/杠上开花再加自摸 1 分；或海底捞月误删门前清。
- 补花后和牌：**计自摸，不计杠上开花**（规则原文）。

### 18. 全不靠 vs 七星不靠 vs 组合龙 的判定顺序
- 七星不靠 = 7 种字牌**全齐** + 序数牌恰 7 张 → 24 分，**不可能再有组合龙**。
- 全不靠序数牌 9 张（三色 147/258/369 齐）→ **全不靠 12 + 组合龙 12 = 24 分**，与七星不靠同分但番种不同。
- 组合龙也可以出现在**普通和型**里（组合龙 9 张 + 一副面子 + 将），此时可另计平和/五门齐/箭刻。
- **常见错算**：把"全不靠 + 组合龙"判成七星不靠；或漏掉普通和型里的组合龙（引擎在"门清"和"1 副露"两种状态下都要单独试匹配组合龙）。
- ⚠️ 存疑：98 规则未规定"组合龙 + 一面子 + 将"的和型，但附录有该牌例；现行规则允许。另外组合龙**龙身上的边/坎/钓是否计**也有分歧（参考实现的 `KNITTED_STRAIGHT_BODY_WITH_ECS` 开关）——测试语料里 `258m23469p14788s3p` 就是两种答案（16 番 vs 17 番）。

### 19. 一色三/四步高 的"宽窄"是否要区分
- 定义是"依次递增**一位数或二位数**"，但**同一手里不能混用**（如 123-234-456 不算）。
- 参考实现有 `DISTINGUISH_PURE_SHIFTED_CHOWS` 开关（默认关），区分后会拆成"一色三步高Ⅰ/Ⅱ"两个番种。
- **常见错算**：允许步长混用；或者对 `123m 234m 345m 456m` 这种同时满足多种解释的牌型重复计番。
- 正解实测：`123m 234m 345m 456m 99p` 门清 → 一色四步高 32 + 不求人 4 + 平和 2 + 缺一门 1 + 单钓将 1 = **40 番**（**不再计一色三步高/连六/老少副**）。

### 20. 「不得相同 / 套算一次」对 一般高·喜相逢·连六·老少副 的封顶
- 牌例：`234567p 234567s` + 东东（门清和东）
- **正确**：门前清 2 + 喜相逢 1 + 喜相逢 1 + 连六 1 + 缺一门 1 + 单钓将 1 = **7 番**
  （或等价的 门前清2 + 喜相逢1 + 连六1 + 连六1 + ... = 7 番）
- **常见错算**：喜相逢×2 + 连六×2 = 8 番。
- 参考实现 A 自己承认这里只是**近似**：
  ```cpp
  // 根据套算一次原则，234567s234567p，只能计为"喜相逢*2 连六*1"或者"喜相逢*1 连六*2"，
  // 而不是"喜相逢*2 连六*2"
  // 直接按规则来写，差不多是图的算法，太过复杂
  // 这里简便处理：先统计有多少番，当超过时规则允许的数目时，从重复的开始削减
  static void exclusionary_rule(...)
  ```
  → 这是**已知会出错的区域**，也是两套引擎最容易分歧的地方。若你的 App 要求精确，这里需要按二部图匹配来做，而不是贪心削减。
